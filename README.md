# Skin Statue · Minecraft 皮肤工作台

本地运行的 Minecraft Java 版皮肤 3D 预览工具。Python 解析皮肤，Three.js 渲染皮肤姿势与手持物品，皮肤数据与预览资源均保留在本机。

当前提供单人头颅与多人场景、独立人物姿势和位置编辑、皮肤解析、实例资源扫描、运行时方块索引导入、逐面调色板、可调尺寸的方块雕像生成、双模式 3D 预览、点击选材与固定分组编辑、草稿与工程文件、正版用户名导入和 `.schematic` 结构导出。辅助模组从 GTNH 客户端导出真实注册信息与已加载纹理。

## 启动

使用 Windows、Conda 和 Python 3.12。项目当前使用 `mc_env` 环境。

```powershell
conda activate mc_env
python -m pip install -r requirements.txt
python run.py
```

打开 [本地预览界面](http://127.0.0.1:8765)。也可以双击项目根目录的 `start.bat`，该脚本通过 Conda 使用 `mc_env`。页面右上角点击“停止服务”会请求当前 Python 服务正常退出，正在处理的任务结束后进程关闭；页面显示退出提示。终端也可按 `Ctrl+C` 停止服务。该按钮需要通过 `run.py`／`start.bat` 启动，外部 Uvicorn 托管会提示使用对应启动方式。

```powershell
python run.py --port 8766
python run.py --debug
python run.py --index block-index-20261115-210250-154.zip
```

`--port` 修改监听端口；`--debug` 开启解析结果、UV、生成统计和服务调试日志，默认关闭；`--index` 在启动时载入指定运行时索引，界面自动使用唯一预载的调色板。修改启动参数或 Python 代码后重启服务，修改界面文件后刷新浏览器。皮肤预览中的模型和图层控制立即生效；修改雕像生成参数后点击重新生成。

Three.js 0.170.0 和 OrbitControls 已随项目保存，运行时无需访问 CDN。浏览器需要支持 WebGL 2，建议使用开启硬件加速的 Edge 或 Chrome。当前预览不依赖 Minecraft 安装，也不需要启动游戏。

## 使用

1. 打开界面即可查看原创双层示例，也可点击或拖入自己的皮肤 PNG。
2. 标准皮肤手动选择 Steve（4 像素手臂）或 Alex（3 像素手臂），默认 Steve。
3. 左键旋转、滚轮缩放、右键平移；上方按钮切换正面、背面、左侧、右侧、顶部及初始视角。
4. 使用基础层／第二层主开关，或单独切换每个部位。空第二层显示为禁用开关，悬停可以查看有效像素与半透明像素数量。
5. 查看右下角的完整／基础／外层纹理图集，选择导出内容并点击“导出 PNG”。

“原始颜色”关闭光照对颜色的影响；“地面网格”和“自动旋转”独立开关。背景可切换深色、浅色、棋盘。左右方向以角色自身为准。

## 支持的皮肤与图层规则

| 项目 | 当前行为 |
|---|---|
| 64×64 PNG | 标准布局，独立左右四肢，支持 Steve 和 Alex |
| 64×32 PNG | 按旧版 Steve 布局读取，逐面镜像右肢生成左肢，统一为 64×64 |
| 基础层 | 头部、身体、左右手臂、左右腿共六个独立长方体，按 Java 版规则强制不透明 |
| 第二层 | 逐面保留完全透明和半透明像素，独立于基础层；头部每侧外凸 0.5，其他部位每侧外凸 0.25 个纹理单位 |
| 旧版帽子 | 旧格式上方右半区全部 Alpha ≥128 时，按旧皮肤兼容规则清除帽子背景；已有透明区域时保留帽子 |
| 模型判断 | 手动指定；PNG 尺寸无法确定标准皮肤的手臂类型；旧格式固定 Steve |
| 输入限制 | PNG，64×64 或 64×32，文件不超过 2 MB |

现代标准皮肤的不透明第二层按文件保留。基础层强制不透明只应用于当前模型实际使用的六面区域。半透明第二层使用 Alpha 混合显示。未使用的图集区域不会生成模型表面。

该工具展示现代双层皮肤布局，支持为后续面向 MC 1.7.10／GTNH 2.9.0 的雕像生成准备皮肤；原版 MC 1.7.10 的玩家皮肤本身仅使用旧布局。

## 点击编辑、候选切换与工程

切到“方块雕像”后单击方块，选中格显示绿色框，旁边的“方块编辑”（窄窗口位于下方）显示本地化名称、注册名、数字 ID、Metadata、固定分组数量和原始材料。拖动仍旋转视角。拾取根据合并网格交点计算单格坐标，再查询服务端真实体素。

候选用这类方块所覆盖的原皮肤颜色和可见面共同计分，沿用生成时的 Lab 色差、平滑权重和连接纹理偏好。每批 12 个，支持上一批／下一批、点击卡片，以及上一个／下一个候选。一次选择期间排序保持固定。卡片显示纹理和分数，也可以搜索本地化名称、注册名或数字 ID 指定方块。生成时禁用的材料、重力块和其他不适合静态雕像的方块继续排除。

生成完成后，以人物身份及最初分配的 `registry_name + metadata` 为每个体素保存固定分组；旧单人工程沿用原有材质分组。替换、切换候选和重新点击都只作用于该原始分组；例如金块换成黄色羊毛后继续换材质，只修改原金块位置，原有羊毛位置保持独立。工程与草稿保存逐格分组，撤销／重做也保留范围。旧工程缺少分组数据时按打开时的当前材质建立固定分组；此前已经合并的范围需重新生成才能恢复。使用撤销可恢复前一份完整状态。服务内保留最近 20 份快照，支持撤销／重做；重新生成或打开工程建立新的编辑历史。编辑立即刷新材料数量和纹理网格，`.schematic` 及对照包直接导出当前编辑结果。统计中的色差标明为初次生成结果，对照包额外记录替换操作。

“保存工程”下载 `.skinproj` 文件，内容包括规范化皮肤、Steve／Alex 模型、生成选项与图层、实际体素、替换记录、原皮肤目标色、所有安全候选（含 CTM 候选）及六面原始纹理。打开工程可离线继续编辑、替换、重新生成与导出，无需原索引 ZIP。工程保存当前结果与编辑记录，撤销快照仅在当前服务会话中保留。工程恢复后的“原始皮肤 PNG”是工程内保存的规范化皮肤。

“保存一份本地草稿”把相同工程内容写到项目 `drafts/`，每次独立保存；选择列表后点击“打开所选草稿”。草稿需要手动保存，服务重启后仍存在。草稿和根目录工程文件已从 Git 排除。工程上传上限 128 MB，展开总大小上限 512 MB。

本地化名称来自 0.1.2 索引中真实创造栏 ItemStack 的 `getDisplayName()`，跟随导出时的游戏语言；清单同时记录 `language`。旧索引没有名称字段，会显示注册名、ID 和重新导出提示。请替换辅助模组 JAR，重启游戏后重新运行 `/skinindex export`，再导入新 ZIP、重新生成，获得完整的游戏名称。

## 头颅与多人场景

“生成模式与人物”可选择完整人物或仅头颅。头颅模式只预览、采样当前皮肤的头部基础层与外层，保留头部绑定旋转、透明轮廓与外层膨胀；不生成身体、持物或披风。头颅的高度基准为 8 像素乘生成倍率。头颅模式不支持多人，其他人物暂时隐藏，切回完整模式后继续编辑；在头颅模式保存工程只保存当前人物。

完整模式可“添加多个皮肤”，也可“复制当前人物”放置同一个皮肤的多个模型，一个场景最多 32 人。每人独立保留名称、Steve／Alex、图层、姿势、两手物品、披风、位置和大小。通过人物下拉框或直接点击其他人物切换当前编辑对象；上方本地导入和用户名查询只替换当前人物。复制会复制当前设置，随后可独立修改。

位置 X／Y／Z 分别控制左右、上下、前后，单位是皮肤像素，生成时乘场景生成倍率。人物先分别按姿势落地，再应用人物大小和位置，人物大小范围 0.25～4。点击“平移当前人物”，或点击躯干后在手柄工具栏选择“位移”，可拖动世界坐标轴移动整个人物，装备、披风和关节一起移动；左侧位置数值同步更新。躯干的“旋转”仍控制整个人物。“重置位置”恢复位置 0／0／0，“重置关节”只恢复角度。所有皮肤编辑在重新生成后才应用到方块快照。

多人共用选材参数和生成倍率，逐人执行现有逆变换体素采样与颜色匹配，再合并体素，只为最终整体构建一次预览网格。合并与人物分组统计的时间为 O(各人物体素数之和＋场景包围体积)，额外空间为相同量级；逐人匹配沿用原有颜色算法，未测量具体提速比例。整体包围范围沿用单轴 2048 格、1200 万体素限制；位置过远也会扩大包围范围。人物实体重叠时保留人物列表中靠前者的方块，界面提示重叠数量，可移动后重新生成。

每个体素记录“人物身份＋最初材料”固定分组。两人使用相同羊毛时，点击其中一人的羊毛并替换或切候选，只作用于该人物对应的原始范围；多次替换不会合并其他分组。方块详情显示所属人物，材料清单按人物分别统计，导出结构包含整个场景。工程与草稿保存所有来源皮肤、独立人物设置、实际体素和人物材料分组；可离线恢复，原有单人工程仍可打开。

新增 `POST /api/scene/generate` 接收全局生成参数及 `scene`（模式、当前人物 ID、人物列表），单人旧生成接口保留。`/api/pose` 共用人物缩放／位置，支持头颅模式，并返回本次渲染所用的位置供手柄补偿。调试模式记录人物数、分组数和重叠数量，默认关闭。不需要更新辅助模组，继续兼容现有 GTNH 2.9.0 索引；保存工作后重启本地 Python 服务并刷新页面加载本次功能。

请手动检查头部外层轮廓、复制后各人的姿势与持物独立性、躯干平移和位置数值同步、同材料跨人物替换隔离，以及工程／草稿重开后的场景与结构导出。游戏内粘贴与内容检查仍由使用者进行。

## 启动恢复与算法默认值

每次成功导入运行时注册表与纹理 ZIP（包括项目索引、文件上传及 `--index`）后，将原包副本保存到项目 `.cache/preferences/runtime-index.zip`。下一次打开页面时自动读取此副本并重建调色板；移动原 ZIP 不影响恢复，重新导入会替换缓存。连接图仍按现有的实例资源加载流程提供，实例路径不自动保存。

选材策略、优先连接纹理开关和六项算法参数在修改后自动保存到 `.cache/preferences/matching.json`，下次打开恢复。打开工程后使用的选材设置也会成为最近设置。随时点击“恢复算法默认值”，会恢复平衡策略、关闭连接优先并重置六项权重，同时保存默认值。界面显示保存结果，停止服务前等待已排队的设置写入。缓存不提交 Git。

跨启动只恢复以上两项；皮肤、披风列表、姿势、尺寸、图层和其他设置通过明确打开工程／草稿来恢复。更新代码前请保存工程，再停止本地服务并重启。首次更新后重新导入一次 ZIP 即可建立索引缓存。

## 正版 Java 用户名导入

在“导入皮肤”输入 Java 正版用户名，点击“查询皮肤”。服务端依次查询 Mojang 用户名档案、UUID 会话档案和官方纹理图片，自动按皮肤元数据选择 Steve 或 Alex，再复用 PNG 解析与图层流程。无需登录微软账户。该操作需要联网，其他本地导入、编辑及工程恢复可离线使用。找不到用户名、官方限流、网络失败或账号尚未设置自定义皮肤时，界面显示具体原因并保留已有皮肤。

使用的官方端点为 `https://api.mojang.com/users/profiles/minecraft/{username}`、`https://sessionserver.mojang.com/session/minecraft/profile/{uuid}` 与 `https://textures.minecraft.net/texture/{hash}`。纹理档案结构同时依据构建依赖中的 Mojang Authlib 1.5.21 `YggdrasilMinecraftSessionService` 字节码核对。

## 官方披风与多披风列表

用户名查询同时读取会话档案的 `CAPE`，从官方纹理域下载并加入“披风”列表；没有当前披风时显示说明，已有列表保留可手动选择。这里收集公开档案返回的当前披风，不枚举账号未佩戴的全部收藏。要补充其他披风，可在官方账号切换佩戴后重新查询，或一次导入多张本地披风 PNG。支持 64×32 标准图集与最大 512×256 的等比例高清图，单张最多 2 MB，一份工程最多 32 张。列表去重，当前人物任选一张佩戴，也可选择不佩戴、临时隐藏或移除候选。

披风按独立的 10×16×1 长方体和官方六面图集渲染与体素化，绑定肩背上沿，随躯干整体旋转。单击披风或点击“可视化旋转披风”显示一个蓝色局部 Z 轴环，角度限制 0～120°，0 为垂直下垂，正值向后扬起；X/Y 旋转、位移、缩放均锁定。局部 Z 轴沿披风连接上沿，对应人物模型横向的 X 轴，不是人物世界竖直轴或前后轴。数值输入、单轴手柄与“重置为 0°”共用同一参数。

披风候选 PNG、当前选择、显示开关与角度随工程／草稿保存，旧工程默认不佩戴。皮肤预览即时更新；重新生成雕像后披风体素才进入材料统计、预览与结构导出。选材、固定分组编辑和空心主体流程照常工作。其他用户的披风和未佩戴的历史披风不会被当成当前账号拥有的列表。更新后需重启本地服务；游戏内容测试由用户完成。

## 独立滚动、姿势和左右手持物

桌面布局的左侧参数栏与右侧预览区分别滚动。方块编辑面板独立滚动，操作候选时可以继续观察雕像。小屏保留上下布局。

“姿势”提供标准站立以及参考基岩版盔甲架的敬礼、英雄、挥舞、僵尸、康康舞等静态预设；展开后可分别编辑头、躯干、左右臂、左右腿的 X/Y/Z 旋转，范围 −180～180 度。这里保存静态姿势，不播放循环动画。躯干带动肢体关节，左右手持物绑定对应手臂；切换姿势保留装备。模型采用 Y 向上、+Z 正面、+X 角色左侧。“重置”视角会适配当前姿势和物品的包围盒。

先在“左右手持物”填写实例路径，点击“只读载入物品与连接纹理”。从原版图标或新版索引搜索列表选择，或者给每只手单独导入 PNG。允许右手、左手、双手持物；列表选中项应用到勾选的手，每手 PNG 可以独立设置。PNG 最大 256×256、2 MB，最多按 32×32 采样。物品相对各自握持点提供 XYZ 位移（−64～64 皮肤像素）、XYZ 旋转、0.1～4 倍缩放和 0～8 皮肤像素的厚度。厚度 0 在皮肤中显示双面薄片，生成时按世界网格覆盖至少一格，斜面会产生台阶。立方体方块保留完整六面和立方体厚度，调整大小使用缩放；自定义立方体图像要求不透明。

持握默认变换依据 MC 1.7.10 `RenderPlayer` 与 `ItemRenderer`，区分工具、普通物品、弓和立方体方块，左手镜像，并校正 Alex 较细手臂的半像素偏移；用户偏移和旋转围绕握持点应用。物品多层图标按导出时的逐层染色合成。自定义装备渲染器、机器等复杂模型用图标近似并在名称处标明；完整不透明方块使用索引真实六面。这里不模拟拉弓过程、附魔光效或复杂模组的装备模型。

姿势、位置、旋转、缩放、厚度只即时更新皮肤。已有雕像始终保留原体素；点击重新生成后，使用同源矩阵对旋转部位与手持物品逆采样，统一进行颜色匹配、空心处理、预览与结构导出。“站立高度基准”表示 32 像素站立角色的缩放；摆姿势后的实际尺寸以包围盒为准。任意姿势体素范围上限为 1200 万格，超过时提示降低高度。工程同时保存已生成雕像与当前尚未生成的皮肤姿势／持物编辑，重开后分别恢复。

## 连接纹理预览

“连接纹理预览”默认开。读取实例的有效 `.png.mcmeta` 中 `myctmlib.connection` 以及 `config/MyCTMLib.cfg` 的图标列表，按启用资源包优先级加载连接图。只向资源包栈相同的调色板补充连接图，读取过程不修改游戏文件。预览支持 MyCTMLib 的四象限 4×4 布局，依据实际同面图标的四邻及对角拼接，基础图的四角用于不连接区域。可关闭该选项查看基础纹理。MCPatcher／OptiFine 等其他方法及未载入的连接图保留基础纹理，预览下方报告受影响的材料数。动画连接图取首帧。

已载入的连接图、运行时物品元数据及其 PNG 一并保存到工程；重开工程可离线继续显示和选材。也可启动时直接加载资源：

```powershell
python run.py --index block-index-20261115-210250-154.zip --instance '实例的 .minecraft 路径'
```

## 运行时物品与名称映射

辅助模组 0.1.3 在原有方块索引后增加物品阶段，遍历真实物品注册表与创造栏变体，记录物品数字 ID、Damage、NBT、本地化名称、语言键、渲染类型、逐层图标与颜色。方块和物品图集分别读取，避免同名 sprite 指向错误图集。不可捕获的图标保留名称与具体错误，不伪造图像。没有创造栏条目的注册物品额外记录 Damage 0 探测项并标记未获创造栏确认。方块 Metadata 仍是 0～15；物品 Damage 按运行值保存，不套用方块范围。

请替换旧辅助模组 JAR，重启游戏再导出；无需安装第二个模组。旧 0.1.0～0.1.2 索引继续用于方块、姿势和原版图标／自定义 PNG 持物；完整模组物品名称及图标使用 0.1.3 新 ZIP。工具内支持物品搜索分页，界面每页 24 项（API 上限 200），并可点击“物品名称映射”下载 JSON。

也提供只读小脚本，把 ZIP 中的真实映射提取为 JSON，不推测注册名与语言键的关系：

```powershell
python tools/export_item_map.py '导出的 block-index ZIP 路径' --output output/item-mapping.json
```

只有 Python 标准库依赖。旧 ZIP 可提取已有方块映射，并提示缺少物品数据。

## 物品列表、材料外观与分批读取

物品搜索在独立列表展示缩略图、名称、ID 与同外观变体数，每页 24 项。搜索和翻页不改写当前装备。先点击列表选中物品，再勾选右手或左手；未选中物品前勾选框禁用。取消勾选或点击该手的“空手”按钮会清空对应手，保留另一个手。选择其他物品时，所有已勾选的手立即切换为新物品，勾选状态保持不变；同时勾选两手时一起使用当前物品。每手 PNG 导入、类型、位置、旋转、比例和厚度仍可独立编辑，工程保存实际手持图像与绑定设置。

搜索支持空白分词的 AND 和 `!排除词`，词语不要求相邻，忽略大小写。例如 `调律源金 扳手` 同时匹配材料和工具名，`扳手 !顶` 排除名称或 ID 含“顶”的结果。正向词还匹配实际工具说明及导出的材料本地化名。旧索引没有材料说明时无法补出这部分搜索内容，需要 0.1.5 重新导出。相同外观合并后，原材料名称与 ID 别名继续可搜索。

辅助模组 0.1.5 保留普通图标的首帧／多层染色，遇到 Forge 自定义物品栏渲染器时，使用真实 ItemStack 的 NBT 生成 64×64 静态截图，不调用数量与耐久条覆盖绘制。截取一帧后恢复 framebuffer、视口、矩阵、纹理、像素缓冲和着色程序等状态；需要 OpenGL 3 framebuffer 支持，捕获失败记录明确错误，不生成替代纹理。图像的原始像素先哈希去重，只有新外观才编码 PNG 和写 ZIP。动画物品仅保存截取时的一帧。

GTNH 2.9.0 的 `MetaGeneratedTool.getSubItems` 只提供少量默认材质。0.1.5 另外读取实际 `Materials.getAll()` 中耐久为正的工具材料，通过 `getToolWithStats` 逐个生成主材变化、手柄变化的样本，保留原工具电力配置及真实本地化材料名。每次只生成并捕获一个样本，仍受每 tick 约 6 ms 预算约束；`/skinindex status` 显示变体进度。覆盖每种材料在主材／手柄上的外观，不穷举两种材料的笛卡尔积、耐久／电量数值。生成项标记 `variant_source=gt_material_api`，不作为配方或可合成性清单；其他物品继续读取真实创造栏和 NBT 变体。

方块调色板读取流程保持原样。物品使用一个后台线程按 64 个变体分批读取，界面显示已读／总数并每 0.5 秒更新，已加载结果可先搜索和装备。物品 PNG 路径只读取一次；不执行方块 Lab 或接缝分析。读取以速度优先：导入期间缓存每张 PNG 的已解码 RGBA 和每种染色结果，白色染色直接复用原图；以更多内存避免重复解码、缩放和染色。发布记录时同时缓存分词搜索需要的名称与说明文本，搜索时直接匹配缓存；缩略 PNG 与搜索索引保留在当前调色板内，解码／染色缓存随本次导入任务结束释放。同一纹理层与染色组合只合成一次，再按最终 32×32 手持外观合并同注册项的重复变体；数字属性不参与分组，不同颜色图像保留。缩略图缓存并按页加载，搜索翻页不会重解码整包。停止服务或 Ctrl+C 会取消本程序的后台物品任务。

运行时索引的上传 ZIP 与总展开大小均允许 10 GiB（10×1024³ 字节），项目索引读取、文件上传和启动恢复共用该展开限制。更新后保存工作并重启本地服务，再读取已有 ZIP 即可，辅助模组无需更新或重新导出。

设 I 为变体数、U 为不同纹理层组合数，读取合成工作为 O(I+U×32²)，另计搜索别名排序；GT 工具样本数量为 O(工具类型×材料数)。不保存重复 PNG 或一次性创建全材料组合。工程在物品读取过程中保存时，只包含已加载候选的自洽快照，正在使用的持物 PNG 始终保存；要带上完整物品候选库，请等进度完成再保存。原始 ZIP 仍保留所有导出记录，旧索引重新载入也会合并可确定的同外观项，但缺失的 GT 图标必须用新版模组重新导出。

更新后保存工作、停止并重启本地服务。将 `output/skinstatueindex-0.1.5.jar` 替换游戏中的旧版辅助模组，重启游戏并进入世界后导出新 ZIP；无需安装第二个物品模组。本轮只完成构建和静态检查，实际验收重点为多词／排除搜索、勾选换物品、翻页保留装备，以及新 ZIP 的 GT 工具材料颜色和导出时游戏渲染状态。

## 物品三维手柄与刷新保护

在皮肤预览中点击手持物品，或点击左／右手的“可视化修改”按钮，显示三维编辑手柄。位移显示红 X、绿 Y、蓝 Z 的世界坐标轴；旋转显示三色圆环；缩放可拖动轴或中心手柄。勾选“等比缩放”时保留当前物品比例，取消后可分别缩放各轴。“完成”隐藏手柄并保留修改。拖动手柄时相机旋转暂停，拖动结束后恢复。

手柄以实际握持点为中心，旋转与缩放使用握持点局部轴；拖动会立即补偿当前物品矩阵，并同步更新左侧位移、旋转和轴缩放数值。“物品缩放”是整体倍率，新的 XYZ“轴缩放”为 0.01～16 倍，二者相乘。放大后的雕像仍遵守单轴 2048 格和总体 1200 万格的工程范围限制。数值输入与手柄共用设置，工程／草稿保留轴缩放，重新生成雕像后才应用到体素与结构。此功能需要重启本地服务加载新接口，辅助模组无需更新。

姿势预设和旧工程中的整圈角度会换算到 −180°～180°，修正回击预设原有 237°／246° 被接口拒绝的问题。有效数字输入每 50 ms 提交最新参数，允许小数，不再等待输入框失去焦点。修改姿势或持物会切到皮肤模式显示结果，已生成雕像继续保留。手动部件矩阵更新时显式刷新世界矩阵。

页面已经载入皮肤或雕像时，浏览器刷新按钮、F5、Ctrl+R、关闭标签页及导航离开会触发浏览器原生确认。提示文字由浏览器决定，需要页面已有用户交互。这里不会自动保存，保存工程后刷新也会确认；主动点击“停止服务”后不再拦截离开。首次加载这次更新前，请先保存当前工程，再刷新／重启，现有旧页面无法追溯安装离开确认。

本次仅执行构建和静态检查。人工验收：在数字框保持焦点输入角度、连续调整步进，切换回击预设并确认皮肤变化；分别点击左右手并拖动位移轴、旋转环与缩放手柄，对比等比／非等比和数字面板；确认旧雕像不变，生成与工程恢复后轴缩放保留；修改后刷新并选择取消，确认工作仍在。

## 绑定关节三环旋转

在皮肤预览点击头、左右臂、左右腿或躯干，或展开“调整各部位角度”点击对应的“旋转”按钮，即可选中关节。关节模式只显示三色旋转环，隐藏位移、缩放及等比选项。拖动后同步回填 XYZ 角度，姿势预设转为自定义；点击“完成”隐藏手柄。

每个部位的角度输入下方提供“旋转”和“重置”按钮；“重置”把该部位 XYZ 归零到 `0,0,0`，其他部位的局部角度与物品设置保留。三维手柄工具栏也提供“重置关节”，作用于当前选中关节。躯干重置恢复整模初始朝向，四肢与头部仍保留各自角度，手持物品继续跟随手臂绑定。重置立即更新皮肤和手柄，已生成雕像仍需重新生成，结果可随工程保存。

旋转围绕骨骼连接点，头部绕颈部、手臂绕肩部、腿绕髋部。基础层和第二层使用同一个关节变换，手持物品是对应手臂的子对象，旋转手臂时随手臂一起移动。关节保持固定父子绑定，不允许把旋转中心平移到部位网格中心。躯干手柄对应整个模型的根旋转，头、四肢及双手物品一起绕根节点旋转；其他关节的既有角度保留。

坐标单位为皮肤像素：颈／整模根节点 `(0,24,0)`，左右肩 `(±5,22,0)`，左右髋 `(±2,12,0)`。关节父坐标与局部旋转由同一个 `/api/pose` 流程返回，前端用矩阵差量即时显示拖动，生成时复用同一套矩阵。服务器重新计算贴地高度时，拖动中对模型整体使用相同的父坐标补偿，避免所选部位和躯干出现暂时错位；松开后恢复统一的贴地位置。

修改只更新皮肤，重新生成才应用到雕像。关节角度沿用现有工程字段，保存／恢复无需转换，旧工程仍能打开。此次需先保存工程，再重启本地工具加载关节坐标接口；无需更新辅助模组，也没有额外服务进程。

本次执行 Python 编译、Ruff 和 JavaScript 语法检查；按项目约定未运行自动化或界面测试。人工验收：旋转头部、左右肩、左右髋时观察连接点，验证双层一起旋转、装备跟随手臂；在双腿均已抬起的姿势继续拖动一条腿，观察贴地调整时仍保持髋部连接；旋转躯干验证全模型及物品一起转动，完成后检查工程恢复与雕像生成姿势。

## 实例方块与调色板

在皮肤预览下方的“实例方块与调色板”面板填写 `.minecraft` 路径并点击“只读扫描实例”。扫描原版客户端 JAR、`mods/`、`mods/1.7.10/`，以及 `options.txt` 中启用的资源包；资源包列表后项优先，未启用的包不参与覆盖。支持 ZIP 资源包与文件夹资源包。

PrismLauncher 的共享 1.7.10 客户端 JAR 会自动定位；其他目录布局可展开“原版 JAR 路径”填写。资源包覆盖优先于基础资源；若多个基础资源提供同名纹理且没有明确覆盖包，会报告歧义，等待运行时索引确认。

静态起步调色板包含 52 个已知原版状态，包括羊毛、染色黏土、木板、石头和金属块等。逐面读取实际资源，不把 PNG 文件数量当作注册方块数量，也不从纹理文件名推测模组 ID。原版起步 ID 来自 1.7.10 固定映射，尚未绑定目标存档。

完整 GTNH 方块信息通过辅助模组导出后，在同一面板点击“导入游戏导出的索引 ZIP”。界面支持按注册名查询、分页查看六面纹理和代表色、查看排除原因、选择颜色和朝向匹配单个方块，以及导出调色板 JSON。调色板保存在本次服务的内存中，重启服务后重新扫描或导入原始 ZIP。

用户放在项目根目录的 `block-index-*.zip` 可直接从面板点击“读取项目索引”，无需再次选择上传文件；这些索引通过 `.gitignore` 排除。运行时方块数字 ID 按索引原值保留，支持 GTNH 扩展 ID，不再施加原版 4095 上限。Metadata 仍使用索引协议 v1 的 0～15 范围。旧 ZIP 继续支持生成、预览与编辑；查看本地化名称需要用 0.1.2 辅助模组重新导出。

颜色统计计算可见像素的 RGB 均值、D65 Lab、纹理方差、透明比例，以及边带对中心的色差和相邻像素颗粒度。空间指标在统一 16×16 尺度计算，完全透明像素不参与。生成、候选排序和单色查询共用逐面评分：Lab 色差加上平滑度加权的纹理起伏、边框反差和颗粒惩罚。平滑优先加大这三项惩罚，减少重复单块边框。

默认静态候选需要创造栏确认 Metadata、六面纹理完整、不透明完整立方体、普通渲染、无 TileEntity、无染色／自发光／动画，并排除重力方块、依赖世界的纹理或颜色，以及匹配到连接纹理规则的状态。被排除的方块仍保留在注册表中，可关闭“仅静态候选”查看原因。

重力方块始终禁止用于匹配和雕像，包括沙、砂砾、混凝土粉末、铁砧、龙蛋及已确认的模组重力方块。0.1.1 辅助模组增加运行时 `gravity_affected` 和 `class_hierarchy`；旧索引使用核对过继承链的兼容类名，当前用户索引无需重新导出即可排除混凝土粉末等。没有通过数字 ID 或方块名中是否包含 sand/gravity 等字样推测重力属性。

Modernity 等包的 CTM 规则会保留并按 `matchBlocks`、`matchTiles`、数字 ID／Metadata 区间和纹理名筛出相关候选。新索引还记录 `myctmlib.connection` 纹理元数据；旧索引中由 MyCTMLib 创建的 sprite 保守归为连接纹理候选。连接纹理预览默认开启，已实现 MyCTMLib 4×4 连接图的四象限选片；需要通过“只读载入物品与连接纹理”提供与索引相同资源包栈的实例。其他连接规则、特殊渲染、着色器和动态机器外观仍按基础纹理显示，面板报告缺少支持的材料。存在服务器资源包时，运行时像素仍含其覆盖，但相关外部规则待确认，默认候选会排除。

辅助模组面向 Forge 1.7.10／GTNH 2.9.0 客户端，无 Mixin，不注册方块、物品、配方或网络协议。运行时不放置或更改世界方块。新增／移除 JAR 需要重启客户端。`config/skinstatueindex.cfg` 中 `exportOnFirstWorld` 默认开启，`debugLogging` 默认关闭，修改配置后重启游戏。每个客户端会话只自动导出一次；后续可以手动重复导出。

## 生成与查看雕像

先导入皮肤，读取项目中的 GTNH 索引或载入其他调色板，再使用左侧“生成方块雕像”面板。点击生成后自动切换“方块雕像”；上方按钮可以随时切回“原始皮肤”对照，原有旋转、缩放、平移和固定视角继续可用。

| 选项 | 行为与默认值 |
|---|---|
| 主体高度 | 1～6 整数倍，32／64／96／128／160／192 格，默认 96；不含第二层外凸量 |
| 颜色细节 | 逐像素、2×2 或 4×4 像素平均，默认逐像素；平均会简化皮肤颜色图案，几何格数继续由高度决定 |
| 内部结构 | 默认空心，可选实心 |
| 壳厚 | 空心主体保留 1～4 格外壳，默认 1；对主体并集做六邻域腐蚀 |
| 外层最小外凸 | 1～3 格，默认 1；实际外凸取此值与模型标准膨胀量的较大者：头部每侧 0.5×倍率，其余部位每侧 0.25×倍率 |
| Alpha 阈值 | 外层像素 Alpha 达到阈值才生成实体，范围 1～255，默认 128 |
| 匹配策略 | 颜色优先、平衡、均匀平滑优先，调整块内离散度、平铺接缝和颗粒惩罚，默认平衡 |
| 优先连接纹理 | 默认关闭；开启后允许仅因 CTM 被排除的完整静态候选，按暴露面连接能力加权优先选用，实际载入连接图的权重大于只有声明的材料；重力等其他排除条件保持生效 |
| 部位与图层 | 按现有六个部位的基础／第二层开关生成；只关闭主体也能单独生成外层 |
| 方块禁用 | 调色板卡片中取消“允许用于雕像”，下一次生成会排除该状态 |

生成期间浏览器仍可操作。参数、皮肤、模型、图层或调色板变化后保留上次结果，界面提示重新生成。生成失败时保留上次可查看的雕像。

主体使用整数长方体并集；第二层按皮肤模型的膨胀比例逐面投影，取各面通过 Alpha 阈值的区域并集，透明面不会裁掉相邻不透明面的耳尖、帽沿和棱角。外层沿各自法线从膨胀后的表面填至基础盒边界，避免偏移较大时只生成一层薄片而留下空隙；主体占据的位置不被覆盖。带姿势时在局部坐标逆采样相同的外层壳体，使用格中心与左闭右开边界。相邻部位外层发生碰撞时按头部、身体、右臂、左臂、右腿、左腿的固定顺序保留先生成部位。只启用第二层时仍保留壳体，基础盒内保持空白。壳厚和最小外凸以实际方块为单位。

例如 128 格（4 倍）雕像，默认头部外层每侧外凸 2 格，四肢和身体每侧 1 格。原来的“外层偏移”工程参数继续读取，现作为最小外凸量。耳朵等像素轮廓需选择“逐像素 · 完整细节”；2×2／4×4 平均会合并颜色和 Alpha。此次算法修改需保存工作后重启本地服务，再重新生成雕像；已保存的体素和结构保持原样。调试模式日志记录带姿势时各部位、图层的外凸与写入数量，默认关闭。

表面匹配同时比较同一个体素所有外露方向的纹理色，按唯一颜色／可见面组合复用结果。外层内侧或边缘没有直接 UV 样本时，使用该体素已投影表面的平均目标色。未暴露的实心内部与空心内壁使用表面最常见材料填充。材料报告包括全部实际非空气方块，平均色差为表面体素的可见面平均 CIE76，最大色差为所有匹配可见面的最大 CIE76。

预览从实际匹配后的方块数组提取可见面，剔除相邻不透明体素内面，再贪心合并同方向同纹理矩形。服务端仍以 PNG 图集传输纹理，浏览器把每张贴图拆成独立的 WebGL 2 纹理数组层，以 `flat` 整数索引固定每个面的材质，不再在大图集中手动定位与重复 UV。每 128 层为一个批次，合并后的矩形通过纹理自身的 RepeatWrapping 每格重复贴图。每张预览纹理最高使用 64×64 像素，纹理较多时降低采样尺寸以保持传输图集不超过 4096；原始索引纹理不被修改。“方块代表色”可查看纯色效果，“原始颜色”可关闭预览方向明暗。

平滑权重为 `s`（颜色优先 0、平衡 0.2、均匀平滑优先 0.7）。单块在统一 16×16 尺度分析 Lab 像素明暗和色彩离散度，并比较左右、上下两侧对应像素的 Lab 色差，识别平均边带色无法发现的对角渐变和重复接缝。纹理惩罚为 `均匀权重×(RGB标准差/2.55 + Lab离散度) + 边框权重×max(边带反差, 两侧接缝反差) + 颗粒权重×颗粒度`，再乘 `s`。连接权重有实际 MyCTMLib 图为 1，仅声明为 0.35，再除以 `1+纹理惩罚/4`；连接奖励为 `偏好强度×(4+6s)×连接权重`。因此有明显渐变和花纹的 CTM 材料仍会被惩罚。对图像整体分析，不按模组名或方块名称屏蔽机械方块。

“调整选材算法”提供下列参数，名称与输入框可悬浮查看说明，也可一键恢复默认值。生成、选中固定分组后的候选排序、单色 API 共用参数；工程与草稿保存生成时的参数，重新打开时恢复，旧工程使用新默认值。调参后需重新生成才应用，原有编辑结果保持原样。

| 参数 | 默认／范围 | 影响 |
| --- | --- | --- |
| 颜色均匀偏好 | 3／0～10 | 提高后更排斥块内渐变、色斑，偏好颜色均匀的材料 |
| 边框与接缝抑制 | 3／0～10 | 提高后更排斥外框和重复铺设时的接缝 |
| 颗粒抑制 | 0.75／0～10 | 提高后更排斥密集细碎纹理 |
| 连接纹理偏好强度 | 0.5／0～3 | 仅在勾选优先连接纹理时生效；0 关闭奖励但保留候选资格 |
| 允许增加色差 | 10／0～30 | 相对最接近颜色的候选最多可额外增加的 CIE76 色差；提高可选范围，也可能偏色；0 仅选最接近颜色 |
| 建筑材料优先强度 | 1／0～3 | 提高常用建筑和私人维度材料的优先级；0 关闭经济偏好 |

超出色差预算的材料排到候选表后面（分数 1000 起），仍可手动选用。加载了实际连接图时，完整连接区域的颜色与纹理指标占 80%、基础图占 20%，按真实暴露面评分。报告显示可用连接图和初次选用材料数量；勾选偏好却没有连接图时提示先载入实例资源。连接图的内部若本身有明显花纹，游戏里仍会保留这些花纹。

建筑材料分为三级：第一档是 GTNH 2.9.0 PersonalSpace 允许的分层／路网／边界／中心／间隙材料，以及羊毛、明确注册名的混凝土系列、Ztones（图中 Iszm／Sols 所属的装饰方块模组）；第二档是实际 `buildingBlocks` 创造分类、旧索引已知的原版建筑方块和 Chisel 建筑系列；第三档为其他材料。每下降一级增加 `12×建筑材料优先强度` 的代价，之后仍受相同色差预算约束，平滑和接缝惩罚仍生效。颜色优先策略只关闭纹理惩罚，经济偏好单独控制。此分类是材料偏好，不估算具体配方价格，也不扩大原有安全候选范围。

内置清单对应 [GTNH 2.9.0 官方 personalspace.cfg](https://raw.githubusercontent.com/GTNewHorizons/GT-New-Horizons-Modpack/2.9.0/config/personalspace.cfg)，按真实 metadata 范围匹配，例如 `chisel:factoryblock2:0-3` 不会扩成全部变体。载入实例资源时只读其 `config/personalspace.cfg`，用实际允许清单覆盖默认清单，并随工程保存。基岩虽然出现在维度配置中，也不会提升为优先建筑材料。混凝土粉末仍按此前的重力规则排除。旧 ZIP 可直接使用；辅助模组 0.1.4 额外记录真实创造分类，重新导出后能识别更多分类，旧工程缺失的建筑偏好参数按默认值 1 处理。选中方块及候选卡片显示分类标签，API 同时返回分类来源。

这些修改需要保存工作、停止服务并重启后重新生成。新模组位于 `output/skinstatueindex-0.1.5.jar`，替换游戏中的旧版 JAR 并重启游戏后再导出，安装步骤见辅助模组 README。披风导入入口采用独立块布局，旋转与重置／移除按钮使用带间距的网格，避免窄侧栏中按钮重叠。

建议先选“均匀平滑优先”并使用默认细调值。还想减弱机械面板感时，提高颜色均匀偏好和接缝抑制；若纯色材料因偏色无法入选，再逐步提高允许增加色差。生成尺寸、壳厚、外层最小外凸、Alpha 阈值、匹配策略、连接预览以及持物参数也提供悬浮说明；例如 Alpha 阈值越低，越多半透明像素会生成方块。

更新后先保存现有工作，再通过页面停止服务并重新启动。新的评分需要重新生成雕像才生效；工程里已经编辑的方块保持原样。

“优先连接纹理”影响材料选择，“连接纹理预览”仅影响显示，两者独立。预览按真实体素邻接及同一面图标身份连接，使用相邻四方向和满足边相连的四个对角选择四象限。不同材料若引用相同图标，也按 MyCTMLib 的图标规则连接。切换显示不重新生成、不修改方块 ID 或结构。其他 CTM 方法显示基础图并报告。

不同高度以相同屏幕玩家比例显示，实际尺寸、体素数、第二层方块数、材料数量和色差显示在“雕像材料与匹配统计”中；雕像模式地面网格间距对应一格。现有 PNG 功能继续用于皮肤和视角截图。

## 导出结构并在游戏中查看

生成后，左侧“导出雕像结构”提供 `.schematic` 和“结构与材料对照包 ZIP”。导出严格使用当前已生成预览的体素快照，保留所有内外方块、空气和 Metadata，不重新选择材料。调整参数后可以导出上次已生成结果，也可以重新生成后再导出新结果。

| 导出模式 | 编码与适用范围 |
|---|---|
| GTNH WorldEdit · 扩展 ID（默认） | `Blocks` 低 8 位、`AddBlocks` 中间 4 位、`AddBlocks2` 高 4 位，支持 0～65535；针对实例中的 `worldedit-v0.0.10` 读取器核对 |
| 传统 MCEdit / WorldEdit | `Blocks` 与 `AddBlocks`，支持 0～4095；当前雕像使用超限 ID 时明确拒绝导出，不截断或替换方块 |
| GTNH Schematica · SchematicPlus | `Blocks` 低 8 位与每格一个字节的 `AddBlocks`；实例中的 `Schematica-1.12.6-GTNH` 需开启 `useSchematicplusFormat=true`；按该读取器有符号 Short 映射行为限定 ID≤32767 |

三种模式均是 GZip 压缩的 NBT Alpha Schematic，扩展名为 `.schematic`。GTNH WorldEdit 与 SchematicPlus 的高位编码不同，按目标加载器选择模式。现代 Sponge `.schem` 不用于本项目的 MC 1.7.10 客户端。

文件同时包含 `BlockMapping` 和 `SchematicaMapping` 注册名映射，供支持它们的读取器转换目标环境的数字 ID。生成报告保留来源索引和资源包顺序。模型仅使用静态完整方块候选，`Entities` 和 `TileEntities` 均为空。

每次导出都将 NBT 实际读回，比较尺寸、数组长度、全部 ID／Metadata、注册名映射和粘贴偏移。数组采用 `index = x + (y * Length + z) * Width`，每层 X 最快、其次 Z、最后 Y。校验失败时不返回文件。这里是导出功能自身的数据校验，游戏加载效果由用户验收。

### 底面中心与可选粘贴站位

单人、头颅和多人都按整体实际体素的最小长方体包围盒确定范围，以其底面几何中心为统一参考。坐标仍为 +X 东、+Y 上、+Z 南；多人不定义共同正面。生成或重开旧工程后默认在长边中点站立：X 边较长或同长时选南边中点，Z 边较长时选东边中点。

“粘贴站位”只允许底部四角和四边中点八个位置。可在雕像预览中直接点击底部圆点，把小人吸附过去，也可用下拉框选择。小人始终面向整体底面中心；标记仅作位置示意，不写入结构。站位设置随工程和草稿保存，更新后需保存工作、重启本地服务并刷新页面；不需要更新辅助模组。不改变已有方块、材料分组或撤销历史。

局部尺寸 `(W,H,L)` 的精确几何中心为 `(W/2,0,L/2)`。传统 Schematic 的 `WEOffset` 是整数，边中点取较小坐标一侧的中心格，偶数边长与精确中点最多相差半格。以玩家所占格为局部锚点 `(Ax,0,Az)`，偏移为 `(-Ax,0,-Az)`，`WEOriginX/Y/Z` 仍为 0；包围盒最低层与玩家脚部所在格同层。`SkinStatue` 元数据另存底面精确中心、所选站位和面向中心的朝向角。界面显示的局部格坐标与实际导出偏移一致。

WorldEdit 普通 `//paste` 不随视线旋转，预览相机也不会改变结构朝向；粘贴时按小人示意选择位置与观察方向。Schematica GUI 使用自身定位方式，不应用 WorldEdit 站位偏移。导出 API 可用 `anchor=auto|northwest|north|northeast|east|southeast|south|southwest|west` 指定站位，省略时采用快照已有选择。

把下载文件放入 `.minecraft/config/worldedit/schematics/`，多人游戏使用服务器目录。站在预定位置，以实际文件名执行：

```text
//schem load mcedit statue
//paste -a
```

ZIP 内结构名固定为 `statue.schematic`。`//paste -a` 只放非空气块；使用 `//paste` 时，空心内部和透明外层留下的空气也会参与粘贴。请在游戏中检查单人和多人导出的偏移，以及更换长边中点／角点后的小人位置与实际粘贴位置。

### 对照包与快照

ZIP 包含 `statue.schematic`、`report.json`、`materials.csv`、`skin-normalized.png` 和使用说明。报告包含源皮肤文件名／哈希、模型、参数、资源包、材料注册名、数字 ID、Metadata、数量、六面图标名、代表颜色及纹理像素来源。颜色与预览有差异时，可据此在游戏中核对具体方块。

服务内存保留最近四次完整生成快照，重启后清空。当前页面使用的快照过期时，下载会提示重新生成，不会静默生成另一个结果。导出文件由浏览器下载，不自动写入游戏实例、服务器或存档。更新 Python 代码或依赖后重启本地服务；界面刷新后重新生成一次，即可使用带导出数据的快照。

每张不同纹理只分析一次，时间与纹理像素总量线性相关。索引状态建立与状态／表面数量线性相关；单色匹配遍历可用候选，时间 O(P)。索引 ZIP 上传上限 10 GiB，总展开大小上限 10 GiB，直接读取且不解压到游戏目录。

雕像体素、固定分组与目标色缓冲区空间 O(V)，编辑快照共享只读分组；纹理分析按图片内容缓存，单次扫描 O(T)（T 为纹理像素总量）；唯一颜色／可见面组合数为 U、可用候选数为 P 时，匹配计算 O(U×P)。隐藏面剔除和空心腐蚀线性遍历体素，网格合并按二维切片连续矩形处理。返回网格以 little-endian Int32 的 Base64 表示，每条记录为 `[x,y,z,face,width,height,tile]`；面顺序为 east／west／up／down／south／north。

导出在同一份裁剪后的状态数组上进行，序列化和读回校验时间与体素数线性相关，额外空间 O(V)。完整体素快照保留在服务端，浏览器通过 `statue_id` 下载对应结果；工程和草稿将当前状态持久保存。候选排序计算 O(Uₘ×P + P log P)，Uₘ 为选中材料的原皮肤颜色组合数；批量替换和网格重建 O(V)，额外体素空间 O(V)。
